     /design-clothes Desktop Studio Layout

     Context

     /design-clothes (app/design-clothes/page.tsx →
     components/design-clothes/ClothingDesigner.tsx) is currently a
     mobile-first, one-step-at-a-time wizard. The user wants a desktop layout
     matching design-mockup.jpg at the repo root: a single-screen "studio" with
     a left style/parts panel, a big center garment preview, a right
     fabric/color panel, and a bottom summary+order band — plus a way to see the
     garment "in any perspective."

     Investigation found:
     - The garment SVG assets (public/assets/garments/**/*.svg) are flat,
     front-facing shapes only — no side/back art exists anywhere.
     - components/garment-creator/* is a fully-built React-Three-Fiber 3D
     mannequin scene, but it is dead code, not mounted anywhere under app/.
     - No AI/backend pipeline generates multi-angle garment images (only
     single-shot text-to-image, unrelated to garments).

     Given this, the "any perspective" request is scoped to 4 honest static
     preview modes (front live render, a derived back view, a fabric close-up,
     and a flat technical-sketch view) rather than a fake 3D/orbit viewer or
     fabricated side art. This was confirmed with the user, along with: keep the
     current mobile wizard completely untouched and only add a new layout at
     lg: (1024px)+, sharing the same Zustand store so state survives resizing.

     Approach

     Build a new desktop studio layout alongside the existing mobile wizard,
     switched via a JS media-query hook (mirroring the existing
     hooks/use-mobile.ts pattern), both reading/writing
     lib/stores/garment-store.ts. Reuse resolveLayers, calcPrice,
     GarmentRenderer, PartPreview, and catalog.json exactly as-is — no changes
     to shared business logic or data. Where the mobile wizard has JSX we'd want
     to reuse (option grids, fabric cards, color swatches, summary tags) but it
     isn't exported, re-implement small local versions rather than modifying
     ClothingDesigner.tsx, to guarantee zero mobile regression risk.

         StudioRightPanel.tsx        # NEW — "2. เลือกผ้า" fabric grid/search, "3.

     Key decisions

     Responsive switch. hooks/use-desktop.ts mirrors hooks/use-mobile.ts's
     matchMedia pattern (1024px breakpoint). DesignStudioRoot.tsx renders a
     shared loading shell until mounted is true (one extra frame), then picks
     DesktopStudio or ClothingDesigner — this avoids both SSR/client hydration
     mismatches and a "mobile flashes then swaps to desktop" flicker. Both
     branches call the same useGarmentStore(), so resizing across the breakpoint
     mid-session preserves the design.

     "Any perspective" = 4 honest views, implemented in viewModes.ts:
     - Front — layers unchanged, exactly today's render.
     - Back — buildBackLayers(layers): filters out a hardcoded Set of part keys
     not visible from behind (collar, pocket, buttons, decoration), then mirrors
     the remaining layers. This is a deliberate, documented simplification
     ("remaining front-safe parts, flipped"), not fabricated back art. If it
     resolves to nothing, show a fallback message instead of a blank canvas.
     - Fabric — bypass GarmentRenderer, show a large tiled swatch of the current
     pattern image.
     - Sketch — toSketchLayers(layers) (strip color/pattern to white) rendered
     through the existing GarmentRenderer, wrapped in a CSS filter (drop-shadow
     edge trick, falling back to grayscale+contrast+invert if that doesn't read
     well) to fake a technical-flat outline look. No changes to
     GarmentRenderer.tsx itself.
     - The back-view exclusion list lives as a local Set<string> in
     viewModes.ts, not a catalog.json schema change — catalog.json is shared
     with the mobile wizard and must stay untouched.
     - Each of the 4 thumbnails in the preview row is a real live small render
     (not a static icon), so it always reflects the current design.
     - Drop the mockup's 2D/3D toggle pill entirely — no 3D backing it.

     Left/Right/Summary panels re-implement (not import) the existing mobile
     step components' JSX patterns locally:
     - Option grids: same tap-to-select card pattern as StepCustomize, using
     PartPreview (exported, reusable).
     - Fabric grid: same card pattern as StepFabric; wire the search box for
     real (client-side name filter); ภูมิภาค/เทคนิคการทอ filters and ผ้าไหม/ผ้าฝ้าย
     tabs render as decorative-but-inert (no such metadata exists in
     catalog.json patterns — don't fabricate fake data, confirmed via grep).
     - Color swatches: same pattern as StepColor.
     - Summary tags + price: same {group, value} tag-building pattern as
     StepDone, plus a new additive calcPriceBreakdown() in types.ts
     (base/options/fabric/total) so the summary band can show itemized pricing
     without touching the existing calcPrice() signature/behavior.
     - Two controls in the mockup have no backing data/logic anywhere
     (ความยาวเสื้อ length accordion, ความเข้มข้นของสี intensity slider) — omit both
     from v1 rather than ship dead controls.
     - Undo/redo buttons in the preview toolbar: store has no history — render
     disabled with a "coming soon" tooltip; wire only Reset (re-applyTemplate)
     and Fullscreen for real.
     - "บันทึกไว้ในรายการโปรด" (save to favorites) — wire to the existing
     lib/wishlist-context.tsx rather than a placeholder (confirmed this store
     exists).
     - Cart/notification icons in the new header — wire to existing
     lib/cart-store.ts / lib/notification-context.tsx for real counts instead of
     static fakes (both already used by components/layout/TopNav.tsx).

     New header is page-scoped. StudioHeader.tsx is a new, separate component
     built for this page only — do not touch or import
     components/layout/TopNav.tsx (a different, MUI-based shared nav used
     elsewhere), to avoid any risk of regressing other routes. Use lucide-react
     icons (already used throughout ClothingDesigner.tsx) rather than pulling in
     MUI.

     Visual language: reuse existing Tailwind tokens already used in
     ClothingDesigner.tsx (bg-primary/text-primary navy #1B2A4A,
     border-secondary/gold #C5A55A, rounded-2xl, shadow-sm, Kanit font,
     framer-motion transitions) — stay consistent, no MUI on this page.

     Step bar (StudioStepBar.tsx) is orientation-only: clicking any of the 4
     pills (เลือกรูปแบบเสื้อ / เลือกผ้า / ปรับดีไซน์ / รายละเอียด & สั่งผลิต) scroll-anchors
     to that section — all sections are simultaneously visible/editable, unlike
     the mobile wizard's linear gate.

     Verified available primitives (checked, exist in repo)

     - components/ui/accordion.tsx, select.tsx, pagination.tsx, breadcrumb.tsx —
     all present, used for left/right panel controls.
     - lib/cart-store.ts, lib/notification-context.tsx, lib/wishlist-context.tsx

     - hooks/use-mobile.ts — existing pattern to mirror for use-desktop.ts.
